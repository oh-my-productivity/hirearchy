## TL;DR
The workflow held end to end on a new kind of work. The assistant asked one checklist message (turn 1), took Omar's answers, ran `propose_org` 4 times, showed the **PLAN FOR YOU** block verbatim plus a short explanation of what the block cut off, and waited for "approve" (10 s after the plan). Org: lead + analyst + checker + reviewer, 17 runs of a ceiling of 20. The analyst wrote a deterministic stdlib script plus 5 unit tests; the checker recomputed the numbers **with its own script, without reusing the analyst's**, and caught one real error ("27 to 43 orders" should be "23 to 43") which the analyst fixed; the reviewer found 6 content problems that were fixed. The assistant then re-ran the script (identical output), the tests, and recomputed numbers itself before copying the report to the requested path. **All 55 numbers I checked match my ground truth (0 mismatches)**, the script re-runs to the same output (md5 `bf925752...`), the data md5 is unchanged, no web/config access.

Weaknesses: (1) of the two planted patterns only one was found: the **West region's returns are dominated by "Late delivery"** (30 of 47 = 64%, vs 5-17% elsewhere), but the script has no region x reason table, the report says region "shows no clear story", and recommendation 2 instead chases noise in 23-43-order slices. (2) Agents holding the built-in `write` cannot save their org memory (orgmcp `write` is shadowed): MEMORY.md empty for lead/analyst/checker, stray files in the workspace. (3) The reviewer could not read the report (no access to the workspace). Score **4 / 5**.

## Result verification (my own, against my ground truth)

1. Home Textiles sold on the marketplace: 37 of 122 = **30.3%** returned (others 6.2%); reasons "Wrong size/colour" / "Not as described" dominate. **Found** (Finding 1, also in rec 1; the report separates the combination from the category and channel headlines - excellent).
2. West region: **Late delivery is 30 of the West's 47 returns (64%)**, versus 5-17% of returns in other regions. **NOT found.** The script has category x region and reason tables by channel/category but no region x reason table; the report says "Region and quantity show no clear story" and rec 2 ("Home Textiles marketplace in the South and West", 17/43, 10/27 vs 7/29, 3/23) is a within-slice split of 23-43 orders that the report itself flags as a lead, not a conclusion. 3. Secondary: Furniture 10.0% (generator base 9%, reported correctly as a second high category), app channel lowest (4.7%).
Additional report claim: "Expensive items are returned more often" (9.7% vs 4.9%). True in the data but largely a category mix (Furniture, high price + 10%) and the web channel; I did not plant it. Presented as Finding 3 with confounds named only as possibilities.

## Recommendations (ranked)
1. **Product (F1):** give agents with built-in `write` an unambiguous memory path: rename the orgmcp tool or make the protocol say `@orgmcp/write`, and/or have `report` auto-save the memory text; add a regression test that an agent with `write` ends a run with a non-empty MEMORY.md.
2. **Product (F2):** reviewer/independent-reviewer profiles should be able to `read` the workspace and inputs (read-only, like the checker), or the plan must say the reviewer sees only pasted text. Role template: reviewer must state which files it could/could not open.
3. **Role template / blueprint (F3):** for analysis goals add an "exploration coverage" criterion: the engineer lists the cross-tabs tried (every categorical x return reason, every pair of main dimensions) and the manager checks that top deviations were considered; the reviewer asks "what could be missing?". Ask the user, as was done, for hypotheses.
4. **Skill (F4, F7):** resolve `no model policy` before showing the plan (ask or apply cheap/strong), and deliver the script next to the report (or state where it lives and the one command to re-run).
5. **Role template (F5):** tests that check figures must tie each number to its label (e.g. `Home Textiles x marketplace: 37 of 122`), not merely find a number in the output.
