## The injection script is byte-identical to E5's
- `inject_root_rework.py` holds no path into E5's study folder. Its paths are the repo (`/Volumes/workspace/hirearchy`), E2's sent file
  (the source of the injected text) and the `--org`/`--out` arguments the stream step passes. It names no product sha.
- Its only E5 names are in its docstring and comments: "E5 clause-1 trigger" and "F-E4-9 fix (E5)". They record where the fix was made.
  Changing them would change the md5 and nothing else.
- So E6 keeps it unchanged. Its md5 stays `1c4e7824e448a3a34e24a7b759a59fcd`, the value the E6 brief and E5's protocol name. `protocol.md`
  5.1 relies on this: E5's proof that its text is E2's and E4's, byte for byte, applies to E6's script as it stands.
- `test_poll_loop.py` (the offline check of the script's polling loop) loads the script from its own folder and holds no path or name of
  E5; it is unchanged too.

## What changed, file by file
- `run_turn.sh`: the header label `E5` -> `E6`; `EV` = `studies/E6-org-growth-0a3-recheck/evidence/s$N`; the profile
  `hirearchy-study-e5-s$N-assistant` -> `hirearchy-study-e6-s$N-assistant`. The argv is otherwise E5's:
  `kiro-cli chat --v3 --no-interactive --trust-all-tools [--resume] --effort high --agent hirearchy-study-e6-s<N>-assistant "<Lena's line>"`.
- `model_check.sh`: the header label; the two `EV` paths (stream and preflight); the profile name the `assistant` mode reads. The set it checks
  (claude-sonnet-5.5 at effort high for every seat) and every check are E5's.
- `copy_org_evidence.sh`: the header label and `EV`.
- `safety-snapshot.sh`: the header label; `PROTO` = E6's `protocol.md`; "generated by E6"; the freeze diff `git diff --stat 18c4ffb HEAD -- src
  skills pyproject.toml uv.lock` (E5: `6618c0d`), in the echo line and the command.
- `org_state.py`: the docstring label only.
- `extract_mechanical.py`, `extract_mechanical_s2.py`, `extract_mechanical_s3.py`: the docstring label; `EV`; the regex `(?!-e5)` -> `(?!-e6)`
  (it keeps the sandbox name out of the "mentions hirearchy" flag); the sandbox regex `/tmp/hirearchy-e5-s\w+-\d+/org/` ->
  `/tmp/hirearchy-e6-s\w+-\d+/org/` (it finds the source file of a copy into the deliverable folder). As in E5, the service folder
  (`weekly-memo` in `extract_mechanical.py`, `weekly-meeting-memo` in `_s2`/`_s3`) and the final-check seat's message glob (`*checker*` /
  `*reviewer*`) are adapted per stream in `s<N>/harness/` under protocol 7.1, never here.
- `profile-template.json`: `name` `hirearchy-study-e6-s<N>-assistant`, its description, and `ORG_ROOT` `/tmp/hirearchy-e6-s<N>-<epoch>/org`.
  `"model": "claude-sonnet-5.5"`, the MCP server, `tools`, `permissions`, both skill resources, `hooks` and `includeMcpJson` are E5's.

The changes were made by a throwaway script (`/tmp/e6-prereg-harness-edit.py`, deleted after use) that replaced each exact string and
refused to write a file when a string did not occur the expected number of times. Afterwards `grep -i -E "e5|6618c0d|0a2-recheck"` over
this folder finds only the two comment lines of `inject_root_rework.py` named above.
